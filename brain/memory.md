## 🧠 Key Decisions Log

### Decision 001 — Technology Stack Selection
**Date:** 2026-09-21  
**Context:** Choosing technologies for the hackathon MVP.  
**Decision:**
- Frontend: React + Tailwind CSS
- Backend: Python + FastAPI
- Database: PostgreSQL + PostGIS
- ML: XGBoost (traffic), YOLOv8 (accessibility detection)
- Maps: OpenStreetMap + OSRM
- Deployment: Docker

**Rationale:** All are open-source, well-documented, and have strong community support. FastAPI provides async performance and auto-generated API docs. PostGIS is essential for geospatial queries. XGBoost is fast to train and suitable for tabular time-series data. YOLO provides real-time object detection.

---

### Decision 002 — Dual-User Architecture
**Date:** 2026-09-21  
**Context:** Whether to build separate apps for commuters vs city planners.  
**Decision:** Single platform with two interfaces (commuter web app + city dashboard) sharing the same backend and database.  
**Rationale:** Reduces maintenance burden, ensures data consistency, and allows the city dashboard to immediately reflect commuter-generated accessibility data.

---

### Decision 003 — BarrierLens as Observation Layer
**Date:** 2026-09-21  
**Context:** How to present AI-detected accessibility features to users.  
**Decision:** All detections are presented as "observations" with confidence scores, not as guarantees. Users can verify or flag incorrect detections.  
**Rationale:** AI object detection is not 100% accurate. Presenting results as guaranteed accessibility could lead to safety issues for people with mobility needs. Human verification adds trust.

---

### Decision 004 — Multi-Objective Routing (4 Priorities)
**Date:** 2026-09-21  
**Context:** What routing priorities to support.  
**Decision:** Four route types: Fast, Green, Reliable, Accessible.  
**Rationale:** Covers the four main user concerns — time, environment, predictability, and accessibility. Each route is scored on all four dimensions so users can make informed trade-offs.

---

### Decision 005 — MVP Scope for Hackathon
**Date:** 2026-09-21  
**Context:** What to build vs what to defer.  
**Decision:** Focus on the critical path: Photo Upload → Accessibility Detection → Traffic Prediction → Route Comparison → Recommendation → Simple Dashboard.  
**Deferred:** Live crowdsourcing, voice assistance, traffic-light control, large-scale real-time integration, mobile native app.  
**Rationale:** Hackathon time is limited. The critical path demonstrates all key innovations: predictive routing, accessibility detection, and multi-objective optimization.

## 📌 Important Context

### Project Positioning
FlowCast is a **decision-support platform**, not a navigation replacement. It combines predictive mobility, sustainability, public-transport reliability, and accessibility into one system. BarrierLens is the **accessibility intelligence layer** — it's part of FlowCast, not a separate product.

### Pilot Area
- Not yet selected — needs to be a small, well-mapped area with available traffic data.
- Consider areas with known accessibility challenges for better demo impact.

### Data Sources (MVP)
- Traffic: Historical or simulated dataset (small, focused on pilot area)
- Maps: OpenStreetMap export for pilot area
- Accessibility: Controlled set of 10-20 locations with manually captured photos
- Transit: Simulated schedules (real feeds in later phases)

## 🐛 Known Issues & Gotchas

| Issue | Description | Status |
| ----- | ----------- | ------ |
| Backend couldn't reach DB in Docker | `.env` pointed at `localhost:5432`; inside the compose network the host is `db`. Fixed by overriding `DATABASE_URL`/`DATABASE_URL_SYNC` in `docker-compose.yml` `environment:`. | ✅ Fixed 2026-09-23 |
| Alembic missing driver | `alembic.ini` uses a sync URL but `requirements.txt` had only `asyncpg`. Added `psycopg2-binary`. | ✅ Fixed 2026-09-23 |
| Migration DDL conflicts with PostGIS | Autogenerated migration tried to re-create GIST indexes GeoAlchemy2 already creates (`if_not_exists=True` added) and to drop/recreate extension tables (`spatial_ref_sys`, tiger geocoder, topology). Extension DDL removed from the migration; `env.py` now has an `include_object` guard so future autogenerate skips extension schemas/tables. | ✅ Fixed 2026-09-23 |
| `osrm` service not running | `ml/data/pilot.osrm` doesn't exist yet (`ml/data` is empty), so compose was started with `docker compose up --build db backend frontend`. Routing is currently stubbed with randomized options, so nothing breaks. | ⏳ Pending pilot data |
| Docker Desktop unstable | Docker daemon crashed twice during image builds; needed a restart + stable-wait before `compose up` succeeded. | ⚠️ One-off |
